## Track Q20 — Multi-corpus AI-first sweep (2026-05-08)

Fifth multi-corpus AI-first sweep on four shape-distinct corpora (vendor-heavy CSS framework with SCSS + JS + Astro doc site; static-site-generator with Liquid / ERB templates and a `_layouts/` envelope tree; vanilla-stack catalog of ~50 sibling demo subdirectories; bulk vendor-template catalog of ~170 sibling subdirectories ~567MB on disk). 5 angles per corpus (`scan_project` / `checklist` / `coverage` / `suggest_fix` / `bootstrap` + `detect_native_wrappers`) returning structured JSON. ~58 raw findings → 18 actionable after dedupe against existing AI-first-consumer doctrine bullets and closed Q15/Q16/Q17/Q18/Q19 items. Two real-world fixtures landed RED (`scss-state-class-line-drift-on-nested-ampersand`, `document-rules-skipped-on-layout-envelope`) pinning the two false-position / false-negative reproducers most cheaply repro'd from sanitized synthetic source. One new doctrine bullet landed: "NextStep prose and structured channels must agree."

- [ ] **Q20-MIN-ENVELOPE-OVERSIZE** Minimum-honest envelope itself crosses host token cap on a 4966-file vendor catalog. `scan_project({summaryOnly:true})` returned 161645 chars; `checklist` 159026; `coverage` 158969; `bootstrap` 145639 — all four project-rooted tools transport-fail with `preDropBytes=189767` / `hardCeilingBytes=96000`. Per "Oversize-success is ambiguous failure" the slim envelope is the closure path; here the slim envelope is itself ~2× over budget. Closure: tighter post-fallback that drops `perRuleCoverage` rows beyond top-N AND `scannedBuildArtifacts` beyond top-N AND `slimTruncations` detail; verify post-serialize size against `hardCeilingBytes` before emit, narrow further if still over.
- [ ] **Q20-NEXTSTEP-CHANNELS-DISAGREE** `nextStep` (prose) and `nextStepStructured` (`{tool, args}`) silently disagree on multiple surfaces: scan_project prose `Scope down further... use restrictToPaths` alongside structured `{tool:"explain_rule"}`; bootstrap prose `narrow scope` alongside structured `{tool:"scan_project", args:{groupBy:"firstChildDir"}}` (aggregation, not narrowing); scan_file on confirmed-vendor file routes structured at a project-rooted tool that already transport-failed. Closure: derive both channels from the same response-assembly predicate; pin via integration test asserting every response with both fields has the structured tool consistent with the prose's action verb.
- [ ] **Q20-SCSS-LINE-DRIFT** `color/state-class-color-only` reports its emit at the line of an earlier nested-block sibling rather than the actual `&.active, &:active` selector. Verified by grepping the corpus file at the reported line (a `.foo[data-popper]` ruleset) and the actual line (the state-class selector). The drift was reproducibly the page-distance between the two — the sibling-`@include` blocks above the state ruleset shifted the AST walk's `loc.start.line` off by N lines. `findingId` (which encodes line) is therefore non-addressable, and `suggest_fix(line)` resolves to the wrong selector. RED-pinned by fixture `scss-state-class-line-drift-on-nested-ampersand`. Closure lives in the SCSS parser or the `walkCssRules` traversal — whichever produces `cssRule.loc.start.line` for nested-`&` rules.
- [ ] **Q20-DOCUMENT-RULES-SKIPPED-ON-LAYOUT-ENVELOPE** `semantics/landmark-main` does not fire on layout files (`_layouts/page.html`, `_layouts/post.html`, `_layouts/default.html`) that carry a full `<html>` / `<head>` / `<body>` envelope but interpolate `{{ content }}` in body. The files are document-shaped (the rendered output IS this file with `{{ content }}` replaced), so document rules belong on the envelope axis, but `meta.template_files_parsed_as_literal` over-broadly gates them off because of the unrenderable directive in body. RED-pinned by fixture `document-rules-skipped-on-layout-envelope`. Closure: separate the fragment / template-directive axes — document-shaped rules run on envelope-bearing files regardless of body-content directive parseability; per-rule confidence may downgrade for body-text-dependent rules but `landmark-main` / `page-titled` / `lang-attribute` are envelope-axis checks.
- [ ] **Q20-CODE-PROP-LITERAL-OVER-EMISSION** Rules emit at `severity:error, confidence:high` inside JSX `<Example code={`...`}/>` template literals: 1108 `navigation/href-empty-fragment` + 452 `navigation/link-no-href` on a doc-site corpus where the `jsx_code_demo_prop_parsed_as_live_dom` warning fires (72 .mdx files affected, propNames=['code']). Reason text hedges `inside code prop in JSX template literal — likely demonstration code, verify before fixing` while severity stays at `error`. Inconsistency: `forms/autocomplete-missing` fires on `<input>` nodes inside the same code-prop literals but `forms/placeholder-as-label` is silent — rule-family suppression-uniformity drift. Closure: when `jsx_code_demo_prop_parsed_as_live_dom` is in `warnings[]` AND emission's parent JSX prop is `code`, uniformly downgrade `severity → info` (or move to `reviewCandidates` surface) across rule families.
- [ ] **Q20-PER-FINDING-CONFIDENCE-NOT-PROPAGATING-PER-RULE-LIMITATION** `keyboard/handler-missing` ships per-rule `coverageConfidence: medium` with reason `cross_file_listener_resolution_not_attempted_by_rule`, but per-finding emissions ship at `severity:warning, confidence:medium` regardless. Observed 43/43 emissions on a vanilla-JS corpus where every selector resolved to a real `<button>` element wired by sibling `.js` — 100% false-positive rate by `confidence:medium`. Per "Per-finding confidence must reflect per-rule coverage limitations": propagate the per-rule degradation to per-finding `confidence` (or echo the reason as additive context in `couldBeWrongBecause`). The `applyPerRuleConfidenceDowngrade` cascade may exist but is not wired through `keyboard/handler-missing`'s emission path.
- [ ] **Q20-SUPPRESS-RECOMMENDED-MISUSED-AS-GUIDANCE** `kind: 'suppress-recommended'` ships when primary advice is an actionable edit rather than a conceded N/A: (a) `aria/dropdown-toggle-triple-aria-missing` returns `kind='suppress-recommended'` with `primary.approach='Add aria-haspopup="menu" and aria-controls=...'` — a real attribute edit; (b) `semantics/heading-hierarchy` ships `kind='suppress-recommended'` on a standalone HTML page with primary advice `Insert an <h1>`; (c) `plan.fixesByClass.suppressRecommended.source: 13` but `suggest_fix` on those findings returns `kind='guidance'`. Per "Suppress-recommended is a distinct discriminator from guidance": tighten the kind-discriminator predicate so `suppress-recommended` requires the rule's evidence model to have conceded the criterion may not apply (e.g. `fragment_input_no_document_envelope`, `parent_layout_supplies_envelope`); when primary advice is a positive edit, route to `kind: 'verify-in-source'` or `kind: 'guidance'`.
- [ ] **Q20-CROSS-SURFACE-ACTIONABLE-COUNT-DRIFT** Silent 1-count disagreement on the actionable-manual-items counter across project-rooted surfaces on identical cwd: `scan_project=23`, `bootstrap=23`, `checklist=22`, `coverage=22`. The cross-surface count invariant requires shared computation; observed drift is on the same conceptual counter rendered through two different code paths. Closure: shared tally helper as canonical source consumed by all four surfaces; pin via integration test on identical cwd.
- [ ] **Q20-VENDOR-PRIORITY-ASYMMETRIC-ACROSS-RULES** Vendor-classification (`vendor-library-version-detected: jquery`, `definite-vendor-distribution`) propagates uniformly to timer rules — `setTimeout` / `setInterval` review-candidates dim to `priority: 'low'` with `vendorPathHint: true` in reason — but does NOT propagate to `.innerHTML` / `.textContent` candidates emitted from the SAME vendor file. Those ship at `priority: 'high'` with no vendor-aware downgrade. Asymmetric handling on identical evidence is dishonest by rule family. Closure: shared vendor-aware-priority helper consumed by every candidate emitter; when `scanKind: 'buildArtifact'` AND vendor classification is confirmed, every candidate's priority dims uniformly.
- [ ] **Q20-BOOTSTRAP-EXCLUDE-RECOMMENDATION-DRIFT** `bulk_catalog_detected.suggestedExcludes` (5 globs) and `bootstrap.suggestedConfig.exclude` (582 entries) disagree on the same scope. Both ship from project-rooted surfaces classifying the same corpus; the agent that pastes the smaller list gets a vastly less-strict exclude than the larger. Closure: shared exclude-recommendation helper with one canonical output; the two surfaces format it differently (globs vs. explicit paths) but enumerate the same files.
- [ ] **Q20-PERRULE-REMEDIATION-WRONG-TEMPLATE** `perRuleCoverage[ruleId]` ships `skipReason: 'gated_by_level'` (rule requires AAA, scan requested AA) with `remediation: 'files of this extension exist at cwd but were pruned by additionalPaths / exclude / .gitignore / default build-dir skips; rerun with broader scope or unset the path filter that excluded them'` — that remediation describes a different `skipReason` (path-filtering) entirely. Affects `contrast/enhanced`, `motion/animation-from-interactions`, `navigation/link-target-blank-announcement`, `pointer/target-size-enhanced`. Closure: `skipReason → remediation` map fix so `gated_by_level` produces remediation like `re-run with --level AAA` and only `path-filtered` produces the current text.
- [ ] **Q20-PROJECTKIND-COLLAPSES-ASTRO-AND-MDX-INTO-JSX** `detect_native_wrappers.projectKind` and `bootstrap.wrappers.projectKind` ship `'jsx'` on a corpus that is overwhelmingly `.scss` + `.astro` + `.mdx` (a doc site). The classifier collapses Astro / MDX into `jsx`, so an agent reading `projectKind: jsx` assumes a React-style project and may mis-route subsequent calls (e.g. asking about React component-wrapper detection on an Astro corpus). Closure: extend `projectKind` to distinguish `astro` and `mdx` (or `static-site-generator` for the Liquid case) so the discriminator is honest.
- [ ] **Q20-FRAGMENT-CLASSIFICATION-SIGNALS-ALL-FALSE-BUT-KIND-ASSERTED** `meta.fragmentFiles[].fragmentClassificationSignals` ships all-false (`hasHtmlOpener: false, hasLayoutDirective: false, inLayoutsDir: false`) yet `kind: 'layout_include_partial'` is asserted on the same entry. The actual predicate that fired (path-prefix match on `_includes/`) is hidden from the surfaced signals. Affects 14 fragment classifications on a static-site-generator corpus. Per "Heuristic-mislabeled meta sub-fields are dishonest": every asserted `kind` must be derivable from at least one true signal in `fragmentClassificationSignals` (so add `pathSuggestsIncludePartial: true` for the `_includes/` predicate, etc.).
- [ ] **Q20-PARTIAL-PARSE-VS-FRAGMENT-INPUT-REASON-COLLISION** `partialParseFiles[].reason: 'Unclosed <html>'` fires on `_includes/top.html` — but the file is also in `fragmentFiles[]` with `kind: 'layout_include_partial'`, so the `<html>` opener absence is fragment-shape-expected, not parser-bailed. The `partial-parse` token reads as parser-failure when the cause is "fragment input lacks document envelope by design." Closure: distinct reason `fragment_input_no_document_envelope` for files also classified as fragments; reserve `partial-parse` for genuine parser bails on document-shaped sources.
- [ ] **Q20-SKIP-EXTENSION-WARNING-DROPS-AND-DOUBLE-REPORTS** `.mkdn` (1), `.xhtml` (1), `.php` (1) files appear in `detect_native_wrappers.inapplicable.filesByExtension` but are silently absent from `text_source_skipped` and `parser_routable_extensions_skipped` warnings. Separately, `.coffee` (21 files) is double-reported in both `text_source_skipped.parserRoutableExtensions` and `parser_routable_extensions_skipped`. Per "Per-tool lane and warning-set classification must agree" and "Truncation reporters must reconcile across warnings": every parser-rejected text-source extension reaches exactly one canonical skip warning; the other surfaces it via `seeAlso`. Files visible to one classification path must be visible to all parallel paths.
- [ ] **Q20-NO-CONFIG-FOUND-EMPTY-DETAILS** `warnings[]` ships `no_config_found` on all four project-rooted surfaces with `warningsDetails.no_config_found: {}` (empty object). Agent reads the warning name with zero specifics — no `searchedPaths` array, no `cwd` echo. Per "Empty `warningsDetails.<code>: {}` is dishonest": populate with `{ searchedPaths: [...], cwd: <resolved> }` so the agent can decide whether to bootstrap or whether the search missed an existing config.
- [ ] **Q20-LANDMARK-MAIN-HEURISTIC-EMISSION-SPAM** `semantics/landmark-main` emits 30 findings on 10-30 LOC vanilla-demo HTML pages with `couldBeWrongBecause: ['largest_block_guess_unobservable']` at `severity: info, confidence: low`. The rule's own evidence ("which block is the main one?") is by its own admission unobservable on these tiny pages — yet emission still ships, contributing 30 entries to the response payload. Per "Heuristic emission is the symmetric twin of heuristic suppression": gate emission on `body.children.length > 3` OR `body.LOC > N`, OR move the candidate to `reviewCandidates` surface so the framing is "please verify" rather than "this is real."
- [ ] **Q20-PAIR-RULE-DOUBLE-EMISSION-ON-SAME-ELEMENT** `pointer/drag-alternative` AND `pointer/draggable-no-keyboard-alt` both fire at `severity: warning` on the same `<div draggable="true">` with overlapping criteria (`wcag22:2.5.7` + `wcag22:2.1.1`). The two emissions duplicate fix prose. Worse: `pointer/draggable-no-keyboard-alt` ships `fixClass: 'suppress-recommended'` on a real drag-only-no-keyboard-alternative violation — suggesting suppression where the predicate genuinely fails. Closure: when two rules with overlapping criteria fire on the same element, coalesce into one emission, OR have one rule suppress when its co-rule has already fired with the same criterion set.
- [ ] **Q20-CHECKLIST-NO-MIN-ENVELOPE-FALLBACK** `checklist` transport-fails on a 50-sibling vanilla-demo corpus (response 86260 chars, host-rejected) while `coverage` on identical cwd correctly emits a slim envelope (`warnings: ['response_dropped_files_oversize']`, `items[]` dropped, `nextStep` recommends scope-down). Per "Per-tool lane and warning-set classification must agree": the minimum-honest envelope fallback at `scan_project` and `coverage` must also exist at `checklist`. Otherwise the agent's first call to `checklist` on a bulk-vendor or bulk-demo corpus dies with no actionable diagnostic.
- [ ] **Q20-SCAN-FILE-FINDINGS-EMPTY-ARRAY-AMBIGUOUS** `scan_file` returns `findings: []` (empty array shape) alongside `findingsArrayDropped: true`, `truncated: true`, `totalFindings: 72`. The empty-array form is shape-identical to a clean-zero-finding scan; the truncation discriminator lives only in sibling booleans, not in the field's own shape. Per "Truncated containers must rename or sentinel": rename to `findingsTruncated: { totalFindings, returned: 0 }`, OR ship a sentinel `[{ truncated: true, reason: 'response_dropped_files_oversize' }]` so the field itself signals "no contents shipped."
- [ ] **Q20-BOOTSTRAP-DOES-NOT-PROPOSE-FIXTURE-EXCLUDES** `bootstrap.suggestedConfig.exclude` lists only build-output globs (`dist/**`, `js/dist/**`) while the same response's `warningsDetails.linked_stylesheet_local_unresolved.files` enumerates 14 visual-test fixture files under `js/tests/visual/*.html` and `js/tests/integration/index.html`. The classifier saw the fixtures (the local-unresolved warning fired on them) but did not propose to exclude. Pasting the suggested config leaves the fixtures in scope and the next scan re-emits hundreds of fixture-driven findings the user did not intend. Closure: when fixture-shaped paths surface in a partial-parse-fragility warning, propose them as `excludeCandidates` (separate field from `exclude` so the user opts in rather than auto-excluding test trees that may be authored).
