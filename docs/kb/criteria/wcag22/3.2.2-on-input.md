# 3.2.2 On Input

**Level:** A | **Standard:** WCAG 2.2
**Spec:** <https://www.w3.org/TR/WCAG22/#on-input>

## Why manual

Finders flag `onChange` and `onInput` handlers statically, but determining whether the handler causes an *unexpected* change of context requires understanding: (a) what the handler does at runtime, and (b) whether the user was advised of the behavior before using the component. A `select` that filters a list in-place is fine; one that navigates to a new page without warning is a violation.

## What to verify

> "Changing the setting of any user interface component does not automatically cause an unexpected change of context unless the user has been advised of the behavior before using the component."

Changes of context include:
- Opening new windows.
- Moving focus to a different component.
- Going to a new page.
- Significantly altering page content.

The key qualifier is **unexpected** — if the user has been explicitly advised (e.g., label reads "Select a country to navigate to its page"), a context change is permissible.

## Common failure modes

- A `<select>` element uses `onChange` to navigate to a new URL without prior user instruction.
- A checkbox immediately submits a form on change without a submit button.
- A radio group changes the visible form section and moves focus without user warning.
- An autocomplete input triggers a page navigation when a suggestion is selected.
- A date picker causes a form POST on date selection, bypassing a submit button.

## Attestation guidance

To attach evidence to an `attest` call (`ra11y-kb://criteria/wcag22/3.2.2`):

- Locate all `onChange` / `onInput` / `onSelect` handlers on form controls.
- For each: identify whether changing the control value triggers a context change (navigation, focus movement, submission, major content reorder).
- If a context change occurs, verify the user was advised *before* using the control (adjacent label text, visible instruction, ARIA description).
- Check JavaScript for `window.location`, `router.push()`, `form.submit()`, `window.open()` inside change handlers.

Evidence: list of form controls with change handlers, context change detected (yes/no), prior user advisory present (yes/no), pass/fail per control.
