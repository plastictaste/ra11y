# 2.1.2 No Keyboard Trap

**Level:** A | **Standard:** WCAG 2.2
**Spec:** <https://www.w3.org/TR/WCAG22/#no-keyboard-trap>

## Why manual

Keyboard traps are runtime behaviors — they require navigating into components with a real keyboard and verifying focus can escape. Static analysis can flag `onKeyDown` patterns and `tabIndex` usage but cannot determine at parse time whether a specific key sequence traps focus.

## What to verify

> "If keyboard focus can be moved to a component of the page using a keyboard interface, then focus can be moved away from that component using only a keyboard interface, and, if it requires more than unmodified arrow or tab keys or other standard exit methods, the user is advised of the method for moving focus away."

Note (normative): Since any content failing this criterion can interfere with overall page usability, all content on the web page must satisfy this requirement. This relates to Conformance Requirement 5: Non-Interference.

Components requiring testing: modals/dialogs, date pickers, rich text editors, custom select menus, sliders, carousels, embedded maps, video players, and any widget that manages its own focus.

## Common failure modes

- A modal dialog traps focus inside with no `Escape` handler or close button reachable by keyboard.
- A date picker moves focus into a calendar grid with no documented keyboard shortcut to dismiss.
- A rich text editor (`contenteditable`) intercepts Tab for indentation without a documented alternative exit key.
- A custom listbox captures all key events and prevents focus moving away with Tab.
- An embedded third-party widget (map, video player) traps focus with no way out.

## Attestation guidance

To attach evidence to an `attest` call (`ra11y-kb://criteria/wcag22/2.1.2`):

- Use Tab (and Shift+Tab) to navigate into every interactive component.
- Attempt to exit each component using: Tab, Shift+Tab, Escape, and arrow keys.
- If a non-standard key is required to exit, verify the user is informed (tooltip, visible instruction, ARIA description).
- Test modals, date pickers, custom widgets, embedded iframes, and third-party components.

Evidence: list of tested widgets, exit key sequence used, whether user instruction is present when non-standard key required.
