# `aria/icon-child-missing-aria-hidden`
- **Severity:** warning
- **Scope:** node
- **Satisfies:** `wcag22:1.3.1`, `wcag21:1.3.1`, `wcag22:4.1.2`, `wcag21:4.1.2`
- **Applies to:** .html, .htm, .tsx, .jsx
## What it checks
An icon-font glyph (Font Awesome, Material Icons, Bootstrap Icons, Ionicons, Glyphicons, Icofont) inside an unnamed <button>/<a>/role=button needs aria-hidden="true" — once the parent's accessible name is added, the unhidden glyph will be double-announced.
## Why it matters
Pairs with `semantics/button-name` and `navigation/link-descriptive-text`: those rules surface the parent's missing accessible name; this rule surfaces the icon-side fix the agent will need to land in the same edit pass. Without it, the agent fixes `<button><i class="fa fa-trash"></i></button>` to `<button aria-label="Delete"><i class="fa fa-trash"></i></button>` — and the next scan re-flags the icon under `aria/icon-font-hidden` as a double-announce risk. Surfacing both halves at the first scan closes the issue in one edit. Static detection is load-bearing because the antipattern is mechanical: the same `<i class="fa-…">` shape across every icon-font-using codebase, and the fix is a one-attribute addition.
## Normative quote
> For all user interface components (including but not limited to: form elements, links and components generated by scripts), the name and role can be programmatically determined.
## Good example
```tsx
<button><i class="fa fa-trash" aria-hidden="true"></i></button>
```
## Bad example
```tsx
<button><i class="fa fa-trash"></i></button>
```
