# `aria/icon-font-hidden`
- **Severity:** info
- **Scope:** node
- **Satisfies:** `wcag22:4.1.2`, `wcag21:4.1.2`, `wcag22:1.3.1`, `wcag21:1.3.1`
- **Applies to:** .html, .htm, .tsx, .jsx
## What it checks
Icon-font glyph elements (Font Awesome, Material Icons, Bootstrap Icons, Ionicons, Glyphicons, Icofont) inside a labeled interactive ancestor should carry aria-hidden="true" (or role="presentation") to prevent assistive-tech from double-announcing the glyph alongside the control's accessible name.
## Why it matters
Icon fonts render glyphs through the CSS `::before` pseudo-element, whose content is a private-use-area Unicode codepoint. When the hosting `<i>` or `<span>` sits inside a labeled `<button>` / `<a>` and does not carry aria-hidden, many assistive technologies announce the glyph codepoint (often as garbage or as the family name) alongside the real label — the user hears 'Close, private use character' or the label twice. Hiding the glyph element from the accessibility tree is the WAI-recommended fix because the visible label already conveys the action. Static detection is load-bearing because the antipattern is mechanical (the same `<i class="fa-*">` shape across every icon-font-using codebase) and the fix is a one-attribute addition.
## Normative quote
> For all user interface components (including but not limited to: form elements, links and components generated by scripts), the name and role can be programmatically determined.
## Good example
```tsx
<button aria-label="Close"><i class="fas fa-times" aria-hidden="true"></i></button>
```
## Bad example
```tsx
<button aria-label="Close"><i class="fas fa-times"></i></button>
```
