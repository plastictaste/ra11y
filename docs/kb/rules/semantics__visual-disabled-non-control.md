# `semantics/visual-disabled-non-control`
- **Severity:** warning
- **Scope:** node
- **Satisfies:** `wcag22:4.1.2`, `wcag21:4.1.2`
- **Applies to:** .html, .htm, .tsx, .jsx
## What it checks
Non-interactive elements (<div>, <span>, <a> without href, <li> without an interactive role) styled as disabled — via a class token like 'disabled'/'inactive'/'is-disabled'/'disabled-state', or an inline style declaring 'cursor: not-allowed' or 'pointer-events: none' — must expose the disabled state via aria-disabled='true' or an interactive role. Otherwise the visual disabled signal reaches sighted users but never reaches the accessibility tree.
## Why it matters
WCAG 4.1.2 requires that component states be programmatically determinable. Template UI toolkits often spray the same `disabled` / `inactive` class — or an inline `cursor: not-allowed` — across both real `<button>` controls (where the native `disabled` attribute also lives) and decorative wrappers, list items, or `<div>` / `<span>` surrogates that LOOK disabled but expose nothing to assistive tech. Sighted users see the greyed-out element; screen-reader users hear it as plain prose, with no signal that it is a disabled control. The fix is `aria-disabled="true"` on the host (plus an interactive role like `role="button"` if the element is standing in for a control), or — when the element is genuinely decorative and not a control at all — renaming the class so the markup honest about intent. Severity is `warning` because the static predicate can't rule out intentional visual-only decoration; the agent reading the consumer site is the correct arbiter.
## Normative quote
> For all user interface components (including but not limited to: form elements, links and components generated by scripts), the name and role can be programmatically determined; states, properties, and values that can be set by the user can be programmatically set; and notification of changes to these items is available to user agents, including assistive technologies.
## Good example
```tsx
<div class="card disabled" aria-disabled="true" role="button" tabindex="-1">Coming soon</div>
<span class="inactive" aria-disabled="true">Filter unavailable</span>
<button class="disabled" disabled>Submit</button>
```
## Bad example
```tsx
<div class="card disabled">Coming soon</div>
<span class="inactive">Filter unavailable</span>
<li class="is-disabled">Archived</li>
<a class="next disabled-state">Next &rsaquo;</a>
<div style="cursor: not-allowed; opacity: 0.5;">Locked</div>
```
