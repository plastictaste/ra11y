# `aria/popover-trigger-missing-haspopup`
- **Severity:** warning
- **Scope:** node
- **Satisfies:** `wcag22:4.1.2`, `wcag21:4.1.2`
- **Applies to:** .html, .htm, .tsx, .jsx
## What it checks
Bootstrap-style popover/tooltip trigger (data-*-toggle="popover" or "tooltip") missing the ARIA properties (aria-haspopup for popover; aria-describedby or title for tooltip) needed to make the trigger-popup relationship programmatically determinable.
## Why it matters
WCAG 4.1.2 requires that a UI component's name, role, and properties be programmatically determinable. The WAI-ARIA Authoring Practices model popovers as dialog-shaped widgets (https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) — the trigger must declare `aria-haspopup` so AT announces that activation reveals an additional surface. Tooltips are description-shaped (https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/) — the programmatic link from trigger to tooltip text is established via `aria-describedby` pointing at the tooltip element id, OR (with Bootstrap specifically) via the trigger's `title` attribute, which the library copies into the tooltip body and wires at runtime. Bootstrap-style triggers — both `data-toggle="popover"|"tooltip"` (v4 / generic) and `data-bs-toggle="popover"|"tooltip"` (v5) — are widely shipped without those properties; the visual UI works for sighted users (hover and click reveal the popup), but AT users hear "Help, button" with no signal that there is a popup to open or what it says. This rule fires on the data-attribute-shape (deterministic in-file evidence), gated per-value: popover triggers without `aria-haspopup` emit; tooltip triggers without both `aria-describedby` AND `title` emit. The sibling rule `aria/expanded-on-disclosure` deliberately excludes the popover/tooltip values; this rule fills that gap.
## Normative quote
> For all user interface components (including but not limited to: form elements, links, and components generated by scripts), the name and role can be programmatically determined; states, properties, and values that can be set by the user can be programmatically set; and notification of changes to these items is available to user agents, including assistive technologies.
## Good example
```tsx
<button type="button"
        class="btn"
        data-bs-toggle="popover"
        data-bs-content="Saves the draft to your account."
        aria-haspopup="dialog"
        aria-controls="save-popover">
  Save
</button>
<button type="button"
        class="btn"
        data-bs-toggle="tooltip"
        title="Permanently delete this record">
  Delete
</button>
```
## Bad example
```tsx
<button type="button" data-bs-toggle="popover" data-bs-content="Help text">
  ?
</button>
<a href="#" data-toggle="tooltip">Hover me</a>
```
