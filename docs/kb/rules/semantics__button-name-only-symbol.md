# `semantics/button-name-only-symbol`
- **Severity:** warning
- **Scope:** node
- **Satisfies:** `wcag22:4.1.2`, `wcag21:4.1.2`
- **Applies to:** .html, .htm, .tsx, .jsx
## What it checks
Flags <button> (and JSX button wrappers / role=button) whose computed accessible name is one or two characters drawn entirely from Unicode punctuation/symbol categories — × (close), + (add), - (remove), ? (help), ! (warning), arrows, chevrons, stars, play/pause glyphs. Screen readers announce these as punctuation ('multiplication sign') or skip them, leaving the button with no usable action cue. Add an aria-label naming the action (or include a visually-hidden span inside the button expanding the glyph into words). Sibling of navigation/link-name-only-symbol on the button axis; symbol-only buttons slip past semantics/button-name because the glyph counts as text content.
## Why it matters
Assistive technology decides how to announce a button from its accessible name. When the name is one or two punctuation/symbol codepoints, AT either reads the Unicode-category name verbatim ('multiplication sign', 'left-pointing double angle quotation mark') or skips the codepoint entirely — neither outcome tells the user what the button does. The visual convention (× = close, + = add, ? = help, › = next, ★ = favorite, ⏵ = play) is sighted-only metadata; AT users hear nothing meaningful.

This is the button-axis sibling of `navigation/link-name-only-symbol`. Symbol-only buttons are the canonical false negative of `semantics/button-name`: that rule checks whether the button has *any* text content, and a glyph like `×` or `+` IS text — so the bare-name check passes. The accessible-name predicate this rule applies is stricter: the name must contain a letter or digit somewhere, otherwise AT users get the codepoint pronunciation (or nothing) where the author meant `Close` / `Add` / `Previous`.

Specifically the matched shapes:

  - One- or two-codepoint accessible names (after collapsing whitespace and decoding the four named entities the HTML parser leaves intact: &laquo; &raquo; &lsaquo; &rsaquo; plus &times;).
  - Every codepoint must be in Unicode punctuation (\p{P}) OR symbol (\p{S}) — letters and digits exit the rule (a letter is real text; a digit might be a step number labeled by surrounding context).
  - Buttons with aria-label / aria-labelledby / title overrides stay silent (the override is the real accessible name).
  - Buttons with aria-hidden='true' on themselves are removed from the a11y tree — silent.
  - JSX expression children (`<button>{label}</button>`) are opaque to static analysis — silent.

Distinct from `semantics/button-name` (which fires only on truly empty buttons / icon-only shells) and from the icon-font path it carries (an `<i class="fa-close">` child with no surrounding text). Symbol-only buttons sit in the gap between those two paths.
## Normative quote
> For all user interface components (including but not limited to: form elements, links and components generated by scripts), the name and role can be programmatically determined.
## Good example
```tsx
<button aria-label="Close dialog">×</button>
```
## Bad example
```tsx
<button>×</button>
```
